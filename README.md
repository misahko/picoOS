# Bare-metal RP2040 RTOS

Мінімалістична операційна система реального часу (претемптивний планувальник) для мікроконтролера **RP2040** (Cortex-M0+), написана з нуля на C та ARM-асемблері — без SDK, без HAL, прямий доступ до регістрів периферії.

## Можливості

- Власний **завантажувач другої стадії** (`boot2.S`) для QSPI-флеш.
- Таблиця векторів переривань і `Reset_Handler`, які вручну копіюють `.data` з флеш у RAM та обнуляють `.bss`.
- **Претемптивний планувальник задач** на основі `SysTick` + `PendSV`:
  - до 16 задач одночасно (бітова маска `usedTCB`);
  - 4 рівні пріоритету (черга `taskQueue[4]`, вибір задачі через `FOI` — find-first-set-bit);
  - перемикання контексту вручну на асемблері (`context.S`) через `PSP`/`CONTROL`;
  - три пули стеків фіксованого розміру — `SMALL` (128 слів), `MEDIUM` (512 слів), `LARGE` (1024 слова);
  - примітив синхронізації `EVENT` (`eventWait` / `eventEmit`) для блокування/розблокування задач.
- Ініціалізація системного тактового генератора (XOSC → PLL → 125 МГц).
- Драйвер **I2C** (реєстровий, DesignWare-подібний контролер RP2040).
- Драйвер **SSD1306 OLED-дисплея** (128×64, I2C) із власним фреймбуфером, растеризацією ліній (алгоритм Брезенхема), растровим шрифтом 3×5 і "брудними прямокутниками" (оновлюється лише змінена область екрана).
- Драйвер **UART**.
- Керування GPIO/SIO для світлодіода (демонстраційна задача `blink`).

## Апаратні вимоги

- Плата на базі **RP2040** (наприклад, Raspberry Pi Pico).
- SSD1306 OLED-дисплей 128×64, підключений по I2C (адреса `0x3C`) до пінів **GPIO4 (SDA)** / **GPIO5 (SCL)**.
- Світлодіод на **GPIO25** (як на Pico — вбудований LED).
- UART на **GPIO0** (TX); RX (GPIO1) поки не задіяний.

## Структура проєкту

Судячи з шляхів у `#include`, цільова структура каталогів така (наразі `main.c` та решта файлів не повністю узгоджені між собою — див. «Відомі проблеми»):

```
.
├── main.c                  # точка входу, створення задач, ініціалізація периферії
└── src/
    ├── startup.c            # таблиця векторів, Reset_Handler, HardFault_Handler
    ├── boot2.S              # 2-й етап завантаження (стандартний для RP2040/W25Q-подібної флеш)
    ├── context.S             # PendSV_Handler — перемикання контексту задач
    ├── core/
    │   ├── core.c            # планувальник, TCB, події, тактування, SysTick
    │   └── core.h
    └── drivers/
        ├── rp2040.h          # мапи регістрів периферії (RESETS, GPIO, SIO, PADS)
        ├── i2c.c / i2c.h
        ├── display.c / display.h   # SSD1306 + фреймбуфер + шрифт
        └── uart.c / uart.h
```

## Як працює планувальник

1. `initTask(fn, priority, size)` виділяє стек із відповідного пулу (`SMALL`/`MEDIUM`/`LARGE`), готує початковий кадр стека (imітує апаратне збереження при перериванні: `xPSR`, `PC`, `LR=0xFFFFFFFD`) і додає задачу в чергу `taskQueue[priority]`.
2. `SysTick_Handler` викликається щомилісекунди, обирає наступну задачу через `schedule()` (найвищий непорожній пріоритет → перший встановлений біт) і, якщо задача змінилась, виставляє `PendSV`.
3. `PendSV_Handler` (асемблер, `context.S`) зберігає регістри `r4–r11` поточної задачі в її TCB, завантажує регістри наступної задачі та перемикає `PSP`.
4. Коли задач немає — виконується `idleTask()` (`wfi`).
